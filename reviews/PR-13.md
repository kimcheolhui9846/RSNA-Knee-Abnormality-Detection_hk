## 지적 사항
- [P2] 외부 `folds.csv` 무결성 검증 없음 — pseudo `StudyInstanceUID`가 정확히 한 번씩 있는지, 중복·누락 ID가 없는지 확인하지 않는다.
  파일이 불완전하거나 중복되면 일부 pseudo study가 조용히 학습에서 빠지거나 잘못된 fold에 들어가 CV와 누수 방지 가정이 깨질 수 있다.
  로딩 시 unique ID, 전체 pseudo ID coverage, one-fold-per-ID를 검증하고 외부 folds.csv로 테스트할 것.

| [P2] folds.csv 검증 없음 | **수정** | 확인해 보니 `build_study_table`이 labels와 folds를 inner merge해서, 빠진 ID는 조용히 제외되고 중복 ID는 study가 두 번 들어간다 — 지적이 맞다. `validate_folds()`를 추가해 `load_table`에서 먼저 검사: labels·folds ID 중복, fold 값이 비었거나 정수가 아님, `0..n_folds-1` 범위 밖, 학습에 쓰는 study(`source` gt/pseudo) 중 folds에 없는 것 → `ValueError`. `source=none`(라벨 없는 study)은 학습에 안 쓰므로 folds에 없어도 된다 |

테스트: `validate_folds` 정상 1건 + 깨진 folds 4종(누락·중복·빈 값·범위 밖) + 외부 folds.csv에서 pseudo study 하나를 지운 뒤 `run()`이 그 ID를 담은 에러로 바로 멈추는지 1건.

실데이터 대조: HF에 올린 `labels.csv`(gt 58 + pseudo 4,349)와 `folds.csv`(4,407행)는 중복 0, 누락 0, fold 0–4(880–882개씩)라 새 검증을 통과한다. 따라서 exp002의 기존 CV 결과는 그대로 유효하다.
